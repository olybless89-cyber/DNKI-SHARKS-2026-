# Threat model

Scope: Phases 1–4 as implemented. Streaming threats are listed for Phase 5 design.
Status: **M** = mitigated in code and tested, **P** = partially mitigated, **O** = open / operational.

| Threat                                                    | Mitigation                                                                                                                                                                                                                                                         | Status                                                         |
| --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------- |
| Membership impersonation (knows someone's number)         | Number alone never verifies. Code is sent only to the contact held on the authoritative record; otherwise officer review. One member record ↔ one account (unique index); duplicate attempts audited.                                                              | M                                                              |
| Membership enumeration                                    | Identical response for existing/non-existent/ineligible members; per-user (5/h) and per-IP limits.                                                                                                                                                                 | M                                                              |
| Account takeover                                          | argon2id; 12+ char passwords; progressive lockout; generic errors; session revocation on reset/change; TOTP MFA (mandatory for every privileged role); recovery codes hashed; TOTP replay prevented (`afterTimeStep`).                                             | M (participant MFA optional)                                   |
| Session theft                                             | 256-bit random token, only SHA-256 stored; `__Host-` HttpOnly Secure SameSite=Lax cookie; absolute + idle expiry; privileged sessions 10 h; role change revokes sessions; logout revokes server-side.                                                              | M                                                              |
| CSRF                                                      | Mandatory `x-dnki-csrf: 1` header on all writes; no CORS; SameSite=Lax.                                                                                                                                                                                            | M                                                              |
| Payment spoofing (redirect / screenshot / client message) | Only `applyVerifiedPayment` after server-to-server verification marks success; validates reference, amount, currency, status.                                                                                                                                      | M                                                              |
| Forged webhooks                                           | Provider signature (Paystack HMAC-SHA512, Flutterwave verif-hash, sandbox HMAC); rejected events stored and 401 returned; body never trusted — always re-verified.                                                                                                 | M (real-provider signatures to be validated against sandboxes) |
| Duplicate / out-of-order webhooks                         | Dedupe key, order row lock, unique success index, terminal-state guards. Concurrency-tested.                                                                                                                                                                       | M                                                              |
| Money for non-payable registration                        | Held as `needs_review` (duplicate, cancelled, amount mismatch) for finance refund; never auto-fulfilled.                                                                                                                                                           | M                                                              |
| QR cloning / replay                                       | Opaque 256-bit token, no PII; server validation; single-use atomic admission; reissue supersedes; identity check categories; staff see name/chapter to compare. A copied QR used **before** the holder is still a risk → ID checks for higher-security categories. | P (inherent to bearer QR)                                      |
| Concurrent duplicate entry                                | Conditional update in one statement; tested with 30 concurrent scans.                                                                                                                                                                                              | M                                                              |
| Offline scanner abuse                                     | No offline mode; scanner shows Offline state and "do not admit"; supervisor fallback procedure.                                                                                                                                                                    | M (by design)                                                  |
| Broken object-level authorisation                         | Participant endpoints scope by session user; staff endpoints by permission; ownership checks tested.                                                                                                                                                               | M                                                              |
| Privilege escalation                                      | Permissions resolved server-side from `packages/shared/src/rbac.ts`; no self-grant; only `user.manage_roles` (super admin) grants roles; last super admin protected; all grants audited.                                                                           | M (dual approval O)                                            |
| Administrative misuse                                     | Reason required on sensitive actions; append-only audit table (trigger blocks UPDATE/DELETE/TRUNCATE); overrides cannot admit revoked/unpaid credentials.                                                                                                          | M                                                              |
| XSS                                                       | React escaping; strict CSP on web (`next.config.ts`) and API (`default-src 'none'`); only server-generated QR SVG is injected.                                                                                                                                     | M                                                              |
| SQL injection                                             | Parameterised queries throughout; LIKE wildcards escaped.                                                                                                                                                                                                          | M                                                              |
| SSRF                                                      | No user-controlled outbound URLs; provider base URLs from config only.                                                                                                                                                                                             | M                                                              |
| Brute force                                               | Rate limits on auth, codes, membership, scanning; code attempt counters; lockout. Shared store via Redis for multi-instance.                                                                                                                                       | M                                                              |
| Credential leakage in logs                                | Pino redaction of cookies, auth and signature headers; sensitive email bodies scrubbed after delivery; webhook payloads stored minimally; tokens never logged.                                                                                                     | M                                                              |
| Data exfiltration                                         | Least-privilege roles; exports restricted, minimal columns, audited, formula-injection safe.                                                                                                                                                                       | P (DLP / export approval O)                                    |
| Denial of service                                         | Body limits, rate limits, statement timeouts, pool limits. CDN/WAF required in deployment.                                                                                                                                                                         | P / O                                                          |
| Supply chain                                              | Pinned versions + lockfile; `pnpm audit` in CI; `onlyBuiltDependencies` allow-list.                                                                                                                                                                                | P                                                              |
| Backup exposure                                           | Must use provider-encrypted, private, access-logged backups (see DISASTER_RECOVERY).                                                                                                                                                                               | O                                                              |
| Streaming token theft / direct video URL abuse (Phase 5)  | Planned: short-lived signed playback tokens, entitlement re-check on refresh, session limits, watermarking, no public fallback.                                                                                                                                    | O                                                              |

## Residual risks to accept or address

1. Bearer QR screenshots can be shared; enable identity checks for categories where this matters.
2. Email is the only contact channel for membership codes; data quality of the authoritative record decides security.
3. External penetration test not yet performed.
